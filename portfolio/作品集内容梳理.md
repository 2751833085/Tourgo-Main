## 0. 一句话 & 基本信息

**一句话**：Tourgo 是一个在纽约曼哈顿真实街头玩的手机网页游戏平台：一边是"限时拍照寻宝"（Hunts），一边是好友之间的"真人抓人"（Manhunt），两者共用一个 Firebase 后端。

**视频里的正式定位**：*TourGo — A Participation Machine for Urban Exploration and Social Pursuit*（一台用于城市探索和社交追逐的"参与机器"）。旁白的说法是：它是 TripAdvisor 这类常规旅游 App 的替代品，**把日常旅游和城市探索变成游戏**。

### 0.1 项目立意（来自视频的 Context 页和旁白）

| 问题 | 视频里的回答 |
|---|---|
| 它做什么？ | 一台基于位置的"参与机器"，把曼哈顿变成一个可以玩的社交环境。 |
| 给谁用？ | 对城市探索、社交游戏、公共空间互动体验感兴趣的人。 |
| 在哪里发生？ | 曼哈顿真实的城市环境。不在虚拟世界里，而是把街道、公园、地标、公共设施当成玩法系统的一部分——**城市既是界面，也是棋盘**。 |
| 玩的过程中产生什么意义？ | 把熟悉的城市环境重新变成互动、不确定和游戏的空间。通过"在真实空间里移动 + 信息不完整"，探索导航、监视和社交行为怎样变成游戏机制。 |

**两种模式想引发的情绪**（视频 0:27）：

| Hunts 模式（找地点） | Friend 模式（找人） |
|---|---|
| 好奇 curiosity | 紧张 tension |
| 发现 discovery | 不确定 uncertainty |
| 探索 exploration | 追逐 pursuit |
| 重新理解熟悉的地方 reinterpretation of familiar places | 疑神疑鬼 paranoia |
| | 兴奋 excitement |
| | 社交压力 social pressure |

> 总结句："The project aims to create emotional responses through incomplete information and real-time movement in public space."（通过不完整的信息和在公共空间里的实时移动，引发情绪反应。）

**旁白里的产品理念**：
- 前提很简单：本地人或任何人上传一个挑战——其实就是自己喜欢的本地角落的一张照片，再设一个找到它的时间限制。附近想参与的人可以接受挑战。
- Friend 模式："不是在城市里找地方，而是找人。"
- 用寻宝游戏的方式重新理解纽约旅游，带来"高风险的肾上腺素感"，推动用户更爱探索、更大胆，**真正了解这座城市，而不只是看个表面**——"That's the ethos of Tourgo."

### 0.2 两类角色（视频的叙事方式）
- **The Local（本地人）**：在城市里闲逛，发现一个有意思的地方，拍照发布成挑战，留给游客去找。
- **Tourists（游客）**：和朋友碰头，在 Tourgo 上挑一个挑战，开始计时，可以一起找也可以分头找，找到后拍照提交，其他人会看到你完成了挑战。

这个"出题人 / 解题人"的设计，正好把 Hunts 的**创建**和**参与**两条线连了起来。

## 2. 前世今生：分阶段详细内容

### ① 起点（04-03 ~ 04-06）
- 04-03 建仓，只有一行 README。
- 04-06 有人提交了一个 W3Schools 风格的 HTML 模板（标题 "Page Title"、一张占位图），几分钟后被替换为 Firebase Hosting 的标准结构（`firebase.json`、`.firebaserc`、`public/`）。
- **可讲的点**：项目从零开始，第一步就定下了"Firebase 全家桶 + 静态托管"的方向。

### ② First software model（04-08）—— 单文件原型
- 一个 `app.js`（1,064 行）+ 一个 `app.css`（1,105 行）就是整个应用。
- 已经有完整的核心闭环：
  - Google 登录 + **reCAPTCHA v3**，还有一套"短时间内频繁登录 / 登录失败就触发人机验证"的异常检测；
  - Hunt 列表（feed）→ 挑战详情 → **开始 Run（倒计时）→ 逐点拍照 → 全部找到 → 获得 Merit（积分）**；
  - 创建 Hunt（逐个添加打卡点）、个人页、地图页（按坐标推断曼哈顿位置）；
  - Firestore / Storage 安全规则初版。
- 视觉：米白底 + **鼠尾草绿**主色（`#5f6f52`）。
- **可讲的点**：先用最笨的方式（单文件）验证"限时拍照寻宝"这个玩法能不能跑通。

### ③ First version of the program that can run（04-15）—— 第一次大重构
- **架构**：单文件拆成 `lib → services → components → pages → app.js` 的严格单向分层；写了 `ARCHITECTURE.md` 作为团队开发规范。
- **样式**：CSS 拆成 `tokens / base / components / layout / pages / portrait-gate` 分层导入。
- **后端**：第一次加入 Cloud Functions —— 管理员后台接口（`admin-portal-handlers.js`）。
- **新页面**：地图浏览、地图式创建（`create-map`）、创建方式选择（`create-picker`）、赛后复盘（`hunt-review`）、管理员页。
- **素材**：16 个默认头像（男/女/孩子/猫/狗/老鼠/猪/蜥蜴/吸血鬼/食尸鬼……）、曼哈顿浏览地图 SVG。
- **视觉**：换成"苏格兰小木屋 / 精品酒店"气质——羊皮纸米色、深咖啡棕、柔和鼠尾草绿；标题用衬线体 **Cormorant Garamond**，正文 **DM Sans**。
- 开发工具上开始用 Cursor（`.cursor/rules/deploy-after-changes.mdc`：改完就部署）。

### ④ Archive before the next major version（04-19）—— 存档 + 设计系统提取
- 新增 **收藏（Saved）** 和 **排行榜（Rank）**，底部 Dock 形成"Hunts · Saved · ＋ · Rank · Profile"五键结构。
- 出现**两套 UI 主题**：Classical（衬线、复古）和 Material Design（后来改名 NeoUI）。
- `_design-extract/`：从代码里**反向提取出一套设计系统**——颜色 / 字体 token、按钮 / 卡片 / 表单 / Dock / 弹窗的预览页、React UI Kit（HuntCard、RunPage、ProfilePage 等）。文档里定义了文案语气（"温暖、克制、略带文学感，像一本精品旅行指南"）、大小写规则、阴影只用暖棕色不用冷灰等。
- **可讲的点**：这是"第一代设计语言"的完整快照，适合放作品集里做"改版前"的对照。

### ⑤ 多语言尝试（04-20）
- 加入 `i18n.js`，支持**英语 / 西班牙语 / 日语 / 韩语**运行时切换。
- 首页问候语接入 Open-Meteo，显示**纽约本地时间 + 实时天气**（"Good morning!" + 天气）。
- **后来的决定**：到 v1 时多语言系统被**整体移除**，只保留英文（`i18n.js` 变成一个兼容层，注释写明"语言系统已移除"）。
- **可讲的点**：一个"做了又砍掉"的取舍——为了把精力集中在核心玩法和视觉质量上收窄范围。具体原因：【待补】。

### ⑥ 第二轮设计改版（04-23 起）—— 用 AI 设计工具重做全部界面
- 04-23 开始在 Claude Design 里提出需求："重新设计这个网页 app 的全部 UI 界面，包含所有页面，欢迎页、主页、登录页，两个主题都要设计优化"。完整对话保存在 `_design-v2/chats/chat1.md`。
- **迭代过程中提出的反馈（可以做成"设计迭代墙"）**：
  1. Neo 深色模式可读性差 → 修卡片前景色、提高次要文字对比度；
  2. Neo 整体饱和度降低；
  3. 深色模式配色仍不理想 → **重做**；
  4. "背景未必是黑色" → 最终定为**矿物石墨灰**（`#242b2c`），不是纯黑也不偏紫；
  5. 界面不全 → 补齐欢迎页、登录页、所有确认弹窗、顶部横幅通知；
  6. 每日欢迎页改成**几秒后自动消失**的临时界面；补评论（Reviews）界面；
  7. 补网格视图（Grid view）、创建 Hunt、Saved 界面；
  8. 所有带标题界面的顶部高度统一对齐 Profile 页，左侧文字全部对齐；
  9. Active run 顶部偏高、Hunt detail 里 "5 STOPS • 30 MIN" 位置不对 …… 等像素级修正。
- **最终设计语言 NeoUI**（`TOURGO_UI_IMPLEMENTATION_GUIDE.md`）：
  - 字体：标题 **Barlow Condensed**（窄体、大写），正文 Avenir Next / Helvetica Neue；
  - 浅色：暖灰米底 `#ece8df`、**赤陶橙**主色 `#c76a4e`、深松绿 `#3c5b53`；卡片四色：薰衣草 / 蜜桃 / 芥末黄 / 薄荷；
  - 深色：石墨灰底、柔和赤陶、低饱和卡片色；
  - 语言：色块卡片、小圆角板块、硬阴影点缀、窄体大写标题；
  - 加载动画用**数学曲线**：全屏加载用 "Rose Orbit"（玫瑰线），局部刷新用 "Spiral Search"（螺线）；
  - 专门设计了**键盘弹出状态**（登录、地图搜索、创建标题、举报详情），保证输入框不被键盘挡住。
- **规模**：主应用 29 个界面 + Friend 37 个界面，每个都有浅色 / 深色两版。
- **决定**：Classical 主题最终**被放弃**，NeoUI 成为唯一主题（代码里还保留了把旧值 `material-design` 自动迁移到 `neo-design` 的逻辑）。
- **可讲的点**：从"复古衬线 + 咖啡棕"转向"窄体大写 + 色块 + 赤陶橙"，更像一个游戏 / 运动类产品；同时展示自己作为设计决策者如何指挥 AI 工具做出细致修改。

### ⑦ Friend / Manhunt 子应用（04 下旬 ~ 05 初）
在 Hunts 之外新增的第二个玩法：**好友之间在城市里玩真人抓人**。

- **完整游戏流程**（`phase-transitions.js`，由房主端驱动）：
  `创建 / 加入房间（6 位房间码）→ 拍头像并锁定 → 准备确认（所有人都要同意，显示 4/5 agreed）→ 分散期（Runner 先躲，Hunter 等待，身份保密）→ 全屏身份揭晓 5 秒（"You are a Runner." / "You are a Hunter."）→ 追捕期 → 僵局 → 结束（Hunters Win / Runners Win）`
- **默认规则**：分散 2 分钟、追捕 40 分钟、锁定 5 分钟、15 分钟没人被抓就进入**僵局**（Runner 需要"原地不动 + 拍位置照片"，即设计稿里的 "Freeze in place"）。房间 2 小时过期，刷新页面能恢复到上次的房间。
- **抓捕机制**：Hunter 扫 Runner 的二维码，拍照和头像对比确认。
- **头像校验**：云函数调用 **Google Cloud Vision 人脸检测**，确保头像里真的有一张脸。
- **社交**（版本 `4-social`）：微信风格聊天（文字 + 语音，录音上限 60 秒）、在线状态（好友开了房间，列表里直接出现 "Join 123456" 按钮）、10 位 Friend Code 加好友。
- **三套 Dock**：大厅（Start / Ranks / Social / Me）、游戏中（Status / Team / Scan·QR / About）、出局观战（Stats / All chat / Exit）。
- **版本演进**：早期 demo（匿名房间 + QR + 头像捕获）→ `3-tabs`（四标签 + 成就统计）→ `4-social`（社交化重构）→ `4b-dock`（Dock 回顶）。
- 还有一个 5,000 多行的 `public/game/flow-design.html`：整套游戏流程的设计说明页。

### ⑧ 交互打磨（04-25，见 `VERSIONS.md`）
一天内对底部 Dock 做了 **10 个版本**（`dock-mech` → `dock-mech10`），每版都有现象、原因、修复方式和浏览器验证结果。很适合做成"微交互打磨"案例：
- 把 Friend 子应用的交互手感移植到主应用：浮动胶囊 Dock、毛玻璃、按钮按压回弹、卡片阶梯入场（每张卡延迟 42ms）；
- 发现每次换页 Dock 都"跳一下" → 原因是每次路由都重建整个页面 DOM → 去掉入场动画；
- 中间"＋"按钮：按下会下沉、选中态和按压态分不清、图标看不清 → 改了 6 轮，最后定为"浮出 Dock 顶部的赤陶色圆形主按钮"；
- Dock 圆角和选中高亮的圆角统一（都是 15.2px）、Dock 宽度锁定 382.8px，不随屏幕宽度缩放；
- 所有动画都尊重系统的"减少动态效果"设置。
- 同一天修复了**排行榜卡顿**：点 Rank 后马上切走会卡住 → 改成先画骨架、数据在后台加载、过期请求自动作废 → 快速切换 758ms 完成。

## 3. 如何组合：产品结构

```
                         Tourgo（同一个 Firebase 项目）
        ┌──────────────────────────┴──────────────────────────┐
  Tourgo NeoUI（主应用 /NeoUI/）                 Tourgo Friend / Manhunt（/game/）
  限时拍照寻宝                                     好友真人抓人 + 社交
  Google 登录 / 访客                               匿名登录（也能用主应用账号）
  challenges · attempts · users …                 hideSeekRooms · Presence · Chats …
        └──────── 共享：账号 uid、显示名（Friend 可选 "Same as Tourgo"） ────────┘
```

- 两个应用**前端代码完全独立**（Friend 不允许引用主应用模块），只通过 Firebase 账号和显示名"弱连接"。
- Friend 顶部有 "Back to Tourgo"，两个应用可以互相跳转。

## 6. 可以重点讲的设计 / 技术亮点

1. **防作弊的"真实到场"机制**：开始 Hunt 要在 150m 内（已启用）；打卡照片读 EXIF 校验 200m、20 分钟（已实现，目前在 `geo-flags.js` 里关闭）；Friend 头像要过人脸检测；登录有 reCAPTCHA 和异常检测。
2. **城市即棋盘**：曼哈顿按街区分区的自制地图、纽约实时天气问候、Manhunt 的分散 / 追捕 / 僵局节奏设计。
3. **两个玩法共用一套后端**，前端完全解耦：既能单独迭代，又共享账号和社交关系。
4. **设计系统的两次换代**，以及放弃 Classical 主题、砍掉多语言的取舍。
5. **用 AI 工具协作做设计和开发**：Claude Design（改版）、Cursor / Claude Code（开发）、带假设编号的调试日志、Sentrux 架构守门。重点是"我怎么提出要求、怎么验收"。
6. **微交互的打磨方法**：Dock 10 轮迭代，每轮都有"现象 → 原因 → 修复 → 浏览器验证"。
7. **真实的线下试玩**：团队在联合广场完整跑通了两种玩法并拍成视频（第 8 节），证明这不只是概念稿。
8. **不用打包工具**的轻量工程方案：改完刷新就能看，靠查询串更新缓存，靠 `data-app-build` 属性追踪用户在用哪个版本。
